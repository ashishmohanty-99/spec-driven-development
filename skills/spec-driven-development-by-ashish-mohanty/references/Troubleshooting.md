# Troubleshooting

## Gates

| Message | Meaning | Fix |
|---|---|---|
| `plan/tasks exist but spec.md is not "Status: approved"` | A gate was skipped | A human sets the status line. Agents must not |
| `REQ-00X is not covered by any task` | A requirement would never be built | Add `(covers: REQ-00X)` to a task |
| `T-00X references no requirement` | Work nobody asked for | Link it, or delete it |
| `has completed task(s) but no test file names it` | Built but unproven | Put the id in a test name, marker or comment; or run `sdd gen-tests` |
| `placeholder text left in REQ-00X` | Template text was approved | Replace `…`, `<…>`, `TBD` |
| `SECURITY: possible … in spec.md:12` | A credential shape was found | Remove it **and rotate the credential** |
| `spec is shipped but T-00X is not checked` | "Shipped" claims more than the files show | Finish the task, or set the status back |
| `feature directory name is not kebab-case` | The gates cannot address that folder | Rename it: lowercase letters, digits, hyphens |
| `.sdd/config.json is not valid JSON` / `must be …` | A broken config would silently switch settings off, so everything stops | Fix the file |
| `cannot run: … not found` in `sdd regression` | The configured test command is missing | Install it or correct `commands` in config |
| `exists and was not generated by sdd gen-tests` | A hand-written test file has the generated file's name | Rename your file |
| A test names the id but the gate still complains | Another feature uses the same id | Put the feature name in the test file's path |
| Requirement not detected | Wrong syntax | Definitions use a colon: `- REQ-001: …`. Scenarios use a dash: `- REQ-001 — Given …` |

## Tests

| Symptom | Fix |
|---|---|
| `ModuleNotFoundError: playwright` | `pip install pytest-playwright && playwright install chromium` |
| Test skipped: `no UI step matches: '…'` | Rephrase with a [built-in phrase](Test-Automation#3-built-in-phrases-work-with-no-code) or add an `@step` |
| Test skipped: `scenario needs a logged-in user` | Create `.sdd/extensions/ui_login.py` from the example |
| Unit tests fail only under `sdd regression` | They need an environment variable. Add its **name** to `envPassthrough` |
| `commands.test` with `&&` does nothing useful | Commands run without a shell. Point to a script or Makefile target |

## Security gate and proof

| Message | Fix |
|---|---|
| `NOT RUN code-scan` / `dependencies` | Install one of the tools it names for your stack, or switch the layer off with a reason |
| A fixture or example is reported as a secret | Put `sdd:allow-secret` on that line, or `sdd security allow <fingerprint> --reason "..."` |
| A real key is reported | Revoke it at the provider first, then remove it |
| `red-first proof: no red run recorded` | `sdd prove red <feature>` before the code, `sdd prove green <feature>` after |
| `the acceptance tests changed since the red run` | Record red again; if the test was wrong, fix the spec first with `/sdd-sync` |
| `NOT recorded: the tests passed` on a red run | The feature already exists or the tests check nothing; find out which |

## Pentest

| Message | Fix |
|---|---|
| `PENTEST NOT RUN (exit 3)` + "No model is configured" | Set up a local model (no key), or export `STRIX_LLM` and `LLM_API_KEY` in your shell |
| `…is not in pentest.allowedTargets` | Someone authorised to test that host adds it to `.sdd/config.json` |
| `Pass --authorized` | Confirms you may test every target |
| `Refusing to send LLM_API_KEY over plain http` | Use an `https://` API base |
| `Strix is not installed` | `pipx install strix-agent`; Docker must be running |

## Agent behaviour

| Symptom | Fix |
|---|---|
| Agent starts coding without a spec | Check `CLAUDE.md` / `AGENTS.md` contains the Spec-Driven Development block; run `sdd doctor` |
| Agent approved its own spec | Revert the status line. Report it; the skills forbid this |
| Agent asks for your API key | Do not give it. It is told never to ask; the command is yours to run |
| Profile has wrong commands | Correct them under "Human-supplied context"; re-scans keep that section |

## Setup and lifecycle

| Symptom | Fix |
|---|---|
| Not sure what to do | `sdd next` |
| The agent keeps asking setup questions | Answer them once: `sdd questions`, then `sdd answer <id> <value>`; "use the defaults" is fine |
| Acceptance tests were generated in the wrong form | `sdd answer e2e-framework <playwright-python\|playwright-ts\|gherkin>`, then `sdd gen-tests <feature>` again |
| `feature files exist but "commands.e2e" is not set` | Gherkin runs under your own Cucumber runner; put its command in `.sdd/config.json` |
| A phase is being skipped | A teammate switched that check off: `sdd lifecycle` shows which and why. `sdd lifecycle enable <check>` restores it |
| `skipping a check needs a reason` | Add `--reason "..."`; it is recorded for the team |

## FAQ

**Is this a hosted service?** No. It is a package you install; everything stays in your repository. That is also why your key never has to go anywhere.

**Does it work without Claude?** Yes: `sdd init --agent generic` writes `AGENTS.md` and `.agents/skills`.

**Does it work for my language?** Yes. The tool itself needs Python 3.11+ to run, but the project can be in any language: the profile, the build guidance and the generated acceptance tests follow the project's own stack.

**Can I use it on legacy code with no specs?** Yes. `/sdd-sync` writes a baseline spec of observed behaviour for one capability at a time.

**How do I upgrade?** Reinstall the package (or unzip the new skill), then `sdd init --force`, adding `--vendor` if the project carries its own copy. Skills, commands, subagents and templates are refreshed. Your constitution, `.sdd/extensions/`, e2e connector, specs and config are kept.
